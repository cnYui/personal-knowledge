# 2026-04-27 Graph 节点视觉规则

## 背景

- Graph 页面前端渲染层已经确定收敛到 `sigma + graphology`
- 本轮先不引入图片节点、自定义 shader 和外部图标资源
- 节点风格先使用纯几何节点，但要补上“词云式权重感”和按缩放渐进显示标签的能力

## 目标

- 节点连接越多，视觉上越大
- 默认全局视图不堆满标签，优先看结构
- 用户逐步放大后，更多标签按层级显现
- 大图下保持可读性，避免头部节点过大、尾部节点标签污染画布

## 已确认方案

### 1. 节点大小权重

- 节点权重使用连接数 `degree`
- `degree` 定义为当前节点参与的边数量
- 不采用线性放大，避免头部节点尺寸失控
- 默认使用对数映射

建议默认公式：

```ts
size = min(maxSize, 5 + log2(degree + 1) * 3)
```

默认参数：

- `baseSize = 5`
- `sizeScale = 3`
- `maxSize = 18`

设计原因：

- `degree = 0/1` 的尾部节点仍可见，但不会抢视觉中心
- `degree = 8~16` 的中高频节点会明显变大
- 高频节点会继续增长，但增长速率递减，更适合大图

### 2. 标签显示策略

- 标签显示不使用“全部显示”或“固定连接数阈值”两种极端方案
- 改为“缩放等级 + 连接数分位数”双重控制
- 默认只让高权重节点常显标签
- 中低权重节点在放大、悬停、选中时再显示

### 3. 缩放分层默认值

默认分为三档：

- `zoom < 0.9`：显示 `degree` 位于前 `10%` 的节点标签
- `0.9 <= zoom < 1.4`：显示 `degree` 位于前 `25%` 的节点标签
- `zoom >= 1.4`：显示 `degree` 位于前 `50%` 的节点标签

补充规则：

- `hover` 节点始终显示标签
- `selected` 节点始终显示标签
- 被选中节点的邻居节点允许放宽标签显示
- `degree <= 1` 的节点默认不常显标签，只在 `hover / selected` 时显示

### 4. 阈值计算原则

- 不写死为“连接数超过 N 就显示”
- 优先按当前图数据的 `degree` 分布动态计算分位数阈值
- 这样不同用户、不同规模图谱下，视觉密度更稳定

推荐实现思路：

- 先取全部节点的 `degree` 列表
- 按从高到低排序
- 分别取 `top 10% / top 25% / top 50%` 的临界值作为当前视图阈值
- 再结合相机缩放等级判断当前节点是否显示标签

## 本轮不做

- 不引入图片节点
- 不引入 `@sigma/node-image`
- 不写自定义 `NodeProgram` / shader
- 不做头像、地点图标、渐变描边等参考图高级样式

原因：

- 当前第一目标是把“结构可读性”和“权重感”做对
- 先把大小映射、标签渐进显示、交互密度控制稳定下来，再决定是否进入高级视觉定制

## 后续实现注意点

- 标签显示应绑定 sigma 相机缩放状态，不能只在首次布局时静态计算
- 分位数阈值要对小样本做保护，避免节点数太少时出现全部隐藏
- 大小、颜色、标签显隐都要兼容 `hover / selected / neighborhood` reducer
- 如果后续图规模继续增大，需要优先控制标签与边标签密度，而不是继续堆节点样式复杂度
